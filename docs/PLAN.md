## 화면과 경험

1. 시작: '생각만 해도 숨찬 동작. 최악은 당신이 정해요.', 16강·32강 선택, 시작 버튼, 동작 미리보기와 진행 중인 게임 이어하기.
2. 대결: 이미지와 한글 동작 이름 두 개, 현재 라운드와 진행 수. 모바일은 위아래 카드, 넓은 화면은 좌우 카드. 이미지 외에 이름도 버튼의 접근 가능한 이름으로 사용.
3. 결과: 최종 선택 동작, 전체 우승률·대결 승률·집계 건수, 전체 순위, 다시 하기, 링크 복사.
4. 공유 링크: 선택된 운동을 보여주고 새 게임으로 연결. 다른 사람의 실제 게임 기록과 혼동하지 않게 표시.

시각 방향: 차콜 배경과 에메랄드 강조색, Inter·Noto Sans KR, 동작별 정사각형 일러스트를 적용했다. 선택 후 300ms 동안 중복 탭을 차단하고 동작 감소 설정을 존중한다. 실제 모바일 표시와 접근성은 브라우저 검증이 남아 있다.

## 구현된 게임 규칙

- 확정 후보 64개 중 기본 32강과 선택 16강을 제공한다. 64강과 전체 후보 사용 모드는 현재 구현 범위에서 제외한다.
- 사용 가능한 후보 중 중복 없이 무작위 추출 후 무작위 대진. N강은 N개 후보, N-1번 선택.
- 후보가 부족한 라운드는 제공하지 않는다. 전체 후보 수를 억지로 2의 거듭제곱에 맞추지 않는다.
- 선택된 '최악'의 운동이 다음 라운드로 진출. 매 화면에서 선택 방향을 명확하게 표시.
- 전체 후보를 한 번에 쓰는 모드는 초기 범위에서 보류. 검토 후보 전체와 한 게임의 후보 수는 별개.
- 대결 이미지 로드 실패 시 이미지를 숨기고 동작 이름은 유지한다. 후보 세트 버전별 sessionStorage에 게임 ID·후보·선택 내역을 저장하여 새로고침 시 복구한다. 사용자 ID는 저장하지 않는다. 이미지 사전 로드는 후속 검토 대상이다.
- 초기 구현에서 되돌리기·건너뛰기·후보 제외는 생략. 시작 전 동작 도감에서 전체 후보 검색 가능.

## 사용자 구분 없는 통계

- 사용자·익명 사용자 쿠키·기기 ID·핑거프린트 없음.
- 같은 사람이 다시 완료해도 별도 게임으로 반영. '참여자 수' 대신 '완료 게임 수' 표시.
- 서버 발급 game_id는 한 게임의 결과 제출 중복만 방지하며 사용자 식별에 사용하지 않는다.
- 완료된 게임의 유효한 대결만 한 트랜잭션으로 집계. 중단 게임은 제외.
- 우승률 = 최종 우승 수 / 해당 후보가 포함된 완료 게임 수.
- 대결 승률 = 선택된 대결 수 / 출전 대결 수.
- 결과에 분모와 기준을 표시. 기본 순위는 우승률 내림차순, 동률은 우승 횟수, 다음은 고정 ID 순서로 정렬한다.
- 표본이 적은 후보는 집계 건수를 함께 노출. 대진·추출에 영향을 받는 재미용 통계.
- 후보가 추가·제외되거나 묶음이 달라지면 후보 세트 버전으로 통계를 분리한다.

## 데이터와 저장

- `site/lib/movements.json`: 고정 ID, 한글명, 분류, 이미지 경로로 구성된 활성 후보 64개. 후보 검토 이력과 이미지 제작 자료는 `docs/` 및 승인 프롬프트 파일에 보관한다.
- `site/lib/tournament.ts`의 `SET_VERSION`: 현재 후보 세트 버전 `2026-v2-64`. 별도 CandidateSet 테이블 없이 게임마다 버전과 추출 후보를 저장한다.
- `site/db/schema.ts`의 `games`: 게임 ID, 버전, 추출 후보, 선택 내역, 집계 요약, 최종 승자, 생성·완료 시간. 후보·선택 내역·요약은 JSON 문자열로 저장하며 사용자 필드는 없다. 라운드 크기는 추출 후보 수로 결정하고, 완료 여부는 완료 시간으로 구분한다.
- 별도 Match 테이블 없이 저장된 후보와 선택 내역으로 대진을 재생한다. 서버가 발급한 대진의 선택 순서·최종 승자·선택 수를 완료 API에서 검증한다.
- 게임 ID 기본 키와 `completed_at IS NULL` 조건부 갱신으로 중복 완료를 방지한다. 같은 결과 재제출은 성공 응답하고 다른 결과는 거절한다.
- 전체 통계에는 공유 저장소가 필요하다. 브라우저 로컬 저장만으로 전체 통계를 구현하지 않는다.
- 운영은 후보 JSON 파일을 편집하고 후보 변경 시 세트 버전을 갱신한다. 관리자 웹 UI는 후속 범위.

## 남은 작업

1. 초기 DB 마이그레이션을 생성해 SQL·스냅샷·저널을 소스에 포함하고 로컬 D1에 적용한다.
2. 실제 Worker에서 게임 생성·완료·통계 조회, 중복 제출·재시도·중단 게임 제외와 후보 버전 격리를 확인한다.
3. 브라우저에서 16강·32강 완주, 새로고침 복구, 공유 링크, 이미지 표시·로드 실패, 이중 탭, 모바일·키보드 접근성을 검증한다.
4. Docker 이미지 빌드·컨테이너 기동과 재시작 후 데이터 유지를 확인한다.
5. 기존 Sites 프로젝트의 상태를 확인하고 배포 환경의 DB 적용·빌드·동작 검증을 진행한다.

## 조사 범위

CrossFit 공식 동작 라이브러리를 기본으로 하고 공식 WOD·대회 자료와 실제 박스의 자체 교육 목록을 보완 자료로 사용했다. 장비·그립·부하·가동범위·스케일링 조합을 무한히 만들 수 있으므로 '모든 동작의 완결된 목록'으로 주장하지 않는다. 출처가 확인된 검토용 목록을 유지하고, 추가 후보는 근거 확인 후 보완한다. 사진과 영상은 참고 링크이며 재사용 허가로 간주하지 않는다.

## Docker 실행 구성

프로젝트 루트 compose.yaml과 site/Dockerfile로 로컬 Worker를 컨테이너에서 실행. 시작 전 로컬 D1 마이그레이션을 적용하고 named volume으로 결과를 보관한다. 기본 접속 주소는 http://localhost:3000. Compose 구성 검증은 통과했으나 현재 환경의 Docker 소켓 접근 거부로 실제 이미지 빌드와 컨테이너 기동은 미검증. 자세한 실행 방법은 site/README.md 참조.
