# 2026 The Worst Workout

상태: 사이트 초기 구현 작성. 전체 빌드·브라우저 검증·배포는 환경의 DNS 연결 문제로 미완료. 소스와 실행 절차는 ../site/README.md 참조.

## 확정 사항

- 크로스핏 개별 동작 중 주관적으로 최악인 동작을 고르는 토너먼트.
- WOD 이름이나 운동 조합을 후보로 넣지 않는다. 단, 클린 앤 저크처럼 하나의 이름으로 쓰이는 복합 동작은 검토 목록에 유지한다.
- 2026은 서비스 타이틀로 사용하며 후보의 등장 연도를 제한하지 않는다.
- 운영자가 관리하는 고정 후보. 조사 목록에서 사용자가 불필요한 항목을 제거한다.

- 카드에는 이미지와 운동 이름을 표시한다.
- 한국어, 모바일 우선, 크로스핏 분위기와 트렌디한 디자인.
- 로그인 및 사용자 식별 없음. 완료 후 전체 게임의 집계 통계를 보여준다.

## 화면과 경험

1. 시작: 영문 타이틀, '당신에게 최악인 동작을 골라주세요', 라운드 선택, 시작 버튼.
2. 대결: 이미지와 한글 동작 이름 두 개, 현재 라운드와 진행 수. 모바일은 위아래 카드, 넓은 화면은 좌우 카드. 이미지 외에 이름도 버튼의 접근 가능한 이름으로 사용.
3. 결과: 최종 선택 동작, 전체 우승률·대결 승률·집계 건수, 전체 순위, 다시 하기, 링크 복사.
4. 공유 링크: 선택된 운동을 보여주고 새 게임으로 연결. 다른 사람의 실제 게임 기록과 혼동하지 않게 표시.

시각 방향: 차콜/오프화이트에 라임 또는 오렌지 단일 강조색. 체육관 타이머를 연상시키는 숫자, 굵은 한글 타이포, 큰 사진. 선택 후 짧은 피드백을 주며 중복 탭을 차단. 동작 감소 설정을 존중한다. 색상과 사진 스타일은 시안에서 최종 결정.

## 게임 규칙 제안

- 기본 32강과 선택 16강을 구현. 현재 후보 63개로 64강은 제공하지 않음.
- 사용 가능한 후보 중 중복 없이 무작위 추출 후 무작위 대진. N강은 N개 후보, N-1번 선택.
- 후보가 부족한 라운드는 제공하지 않는다. 전체 후보 수를 억지로 2의 거듭제곱에 맞추지 않는다.
- 선택된 '최악'의 운동이 다음 라운드로 진출. 매 화면에서 선택 방향을 명확하게 표시.
- 전체 후보를 한 번에 쓰는 모드는 초기 범위에서 보류. 검토 후보 전체와 한 게임의 후보 수는 별개.
- 이미지 사전 로드와 실패 시 이름 기반 대체 화면. 새로고침 복구는 게임 상태만 sessionStorage에 저장하는 안을 제안한다. 사용자 ID는 저장하지 않는다.
- 초기 구현에서 되돌리기·건너뛰기·후보 제외는 생략. 시작 전 동작 도감에서 전체 후보 검색 가능.

## 사용자 구분 없는 통계

- 사용자·익명 사용자 쿠키·기기 ID·핑거프린트 없음.
- 같은 사람이 다시 완료해도 별도 게임으로 반영. '참여자 수' 대신 '완료 게임 수' 표시.
- 서버 발급 game_id는 한 게임의 결과 제출 중복만 방지하며 사용자 식별에 사용하지 않는다.
- 완료된 게임의 유효한 대결만 한 트랜잭션으로 집계. 중단 게임은 제외.
- 우승률 = 최종 우승 수 / 해당 후보가 포함된 완료 게임 수.
- 대결 승률 = 선택된 대결 수 / 출전 대결 수.
- 결과에 분모와 기준을 표시. 기본 순위는 우승률 내림차순, 동률은 우승 횟수, 다음은 고정 ID 순서로 제안.
- 표본이 적은 후보는 집계 건수를 함께 노출. 대진·추출에 영향을 받는 재미용 통계.
- 후보가 추가·제외되거나 묶음이 달라지면 후보 세트 버전으로 통계를 분리한다.

## 데이터와 저장

- Movement: 고정 ID, 한글명, 영문명, 분류, 변형 그룹, 출처, 활성 상태, 이미지 경로·권리 정보.
- CandidateSet: 버전과 포함 운동 ID. 시작한 게임은 해당 버전에 고정.
- Game: 게임 ID, 후보 세트 버전, 라운드 크기, 추출 후보, 생성/완료 시간, 최종 선택, 완료 상태. 사용자 필드 없음.
- Match: 게임 ID, 대결 순서, 양쪽 후보, 선택 후보.
- 서버에서 후보 포함 여부, 대진 진행, 최종 승자, 선택 수를 검증. 게임 ID 고유 제약과 완료 트랜잭션으로 재시도 중복 방지.
- 전체 통계에는 공유 저장소가 필요하다. 브라우저 로컬 저장만으로 전체 통계를 구현하지 않는다.
- 운영은 초기에는 파일에서 후보 활성 여부를 편집. 관리자 웹 UI는 후속 범위.

## 구현 단계

1. MOVEMENT-CANDIDATES.md 검토: 삭제·통합·추가, 이름 및 범위 확정.
2. 모바일 시작/대결/결과 시안. 더미 이미지로 화면 흐름 검토.
3. 토너먼트 엔진과 게임 상태 복구.
4. 서버 결과 검증, 중복 완료 방지, 영속 저장, 통계 API.
5. 권리 확보한 이미지 적용, 공유 링크와 메타데이터.
6. 16/32/64강 대진, 중복 후보, 이중 탭, 새로고침, 제출 재시도, 중단 게임 제외, 통계 분모, 모바일 접근성 검증.

기술 구성: Vinext + React + Cloudflare D1 + Sites. 사용자 개발 진행 요청에 따라 site/에 구현하고 비공개 Sites 프로젝트를 생성했다. 패키지 설치와 소스 동기화는 각각 npm 및 Git 호스트의 DNS 연결 실패로 중단되어 아직 게시되지 않았다. 초기 DB 마이그레이션 생성·전체 빌드·브라우저 검증은 후속 실행이 필요하다.

## 다음 결정

- 후보 삭제 및 유사 변형 통합 여부.
- 기본 라운드 크기와 모르는 동작 처리 필요 여부.
- 이미지 확보 방식: 직접 제공 / 사용 허가된 사진 / 동작 정확성을 검토한 제작 이미지.

## 조사 범위

CrossFit 공식 동작 라이브러리를 기본으로 하고 공식 WOD·대회 자료와 실제 박스의 자체 교육 목록을 보완 자료로 사용했다. 장비·그립·부하·가동범위·스케일링 조합을 무한히 만들 수 있으므로 '모든 동작의 완결된 목록'으로 주장하지 않는다. 출처가 확인된 검토용 목록을 유지하고, 추가 후보는 근거 확인 후 보완한다. 사진과 영상은 참고 링크이며 재사용 허가로 간주하지 않는다.

## Docker 실행 구성

프로젝트 루트 compose.yaml과 site/Dockerfile로 로컬 Worker를 컨테이너에서 실행. 시작 전 로컬 D1 마이그레이션을 적용하고 named volume으로 결과를 보관한다. 기본 접속 주소는 http://localhost:3000. Compose 구성 검증은 통과했으나 현재 환경의 Docker 소켓 접근 거부로 실제 이미지 빌드와 컨테이너 기동은 미검증. 자세한 실행 방법은 site/README.md 참조.
